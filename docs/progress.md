## 3. Watchlist: status checks

**Cadence rule.** Status checks are event-driven, not a sequential research queue. Check an item immediately when an official depositary notification, signature, ratification, accession, entry-into-force notice, organ decision or other formal act appears. Without such an event, run one consolidated sweep of the watchlist at most once every 30 days. Do not recheck an individual item whose `Last checked` date is less than 30 days old unless an event or a stated deadline applies. Fixed-date events (an AU Assembly, a CCW session, a UNGA plenary) are checked after the event, not before. A sweep updates the `Last checked` dates; that date-only edit may be committed as a single watchlist sweep, but it does not change any record `verified_on` date or create a factual claim. A sweep that finds a new act is handled as a normal record update and logged in [`research-log.md`](research-log.md). Closed checks do not return to this list unless a new act creates a new instrument.

## 5. How to continue without starting over

1. Read `catalog/instruments/coe-cets-225.json` and `corpus/coe-cets-225/manifest.json` as the reference pattern.
2. Add a record by copying an existing JSON, changing the id/title/sources/verification, and placing any acquired file under `corpus/<id>/source/`.
3. Register the URL and hash in `catalog/acquisitions.json`; run `tools/make_manifest.py`.
4. Extract and segment only if a full text is acquired; otherwise set `text.full_text: false` and keep the original. For A/RES/79/1 use `--mode pact`; for an official HTML page use `--mode html` and, where necessary, `--html-start`/`--html-end`.
5. Run `make test`. Fix errors rather than suppressing them. Update `docs/coverage.md` and this file.
